Vigil fleet test, 2026-11-26: findings so far
=============================================

Fleet: 14 instances (10 Alpine containers and 1 bare-metal instance on
Fedora, bare metal on macOS and on two Windows 11 machines), later Windows
Server 2025; every one fetching its configuration from Gitea over https,
every one sending to the LGTM backend over https. Vigil 1.5.3, base pack.

1. Configuration handling: as specified
---------------------------------------
A broken job (wave 3) is set aside as INVALID, the rest of the file runs
(SPECIFICATION 16.3). A file with an unknown section (wave 4) is refused
by every instance, which keeps the configuration it runs; a file broken
only for Windows (wave 7) is refused by Windows only. See wave-*.txt and
grafana-wave-4-refused.png.

2. Log records near a configuration change carry the wrong revision
-------------------------------------------------------------------
SPECIFICATION 14 (Log forwarding): every record carries "the active
configuration revision". The forwarder tags a line with the revision (and
[tags], such as wave) active when it SENDS the line, not when the line was
written. Near a change, lines are attributed to the wrong configuration,
in both directions.

4. A host short of CPU: metrics late, nothing lost
--------------------------------------------------
Fedora (4 cores; also running a demo Vigil and its own Vigil service) with
10 containers: load average 23 at 18:33, 35 at 19:29; sender runs took
minutes; metrics reached Prometheus 4-5 minutes late (e.g. fedora-c2 last
seen 296s before). Spools held the data (Spool bytes, 40 KiB at most). With
6 containers the load fell from 35 to 10 within two minutes (19:30-19:31).

5. Windows: checking the configuration's source costs 5-8 CPU seconds
---------------------------------------------------------------------
vigil_fetch on Windows: cpu 4.89s-7.84s a run (wave-4-unknown.txt), against
0.55s-0.80s on Linux and about 1.1s on macOS: a fifth of a core at a 30s
check_every.

6. Gitea down and broken configuration look the same in metrics
---------------------------------------------------------------
A refused file raises vigil_source_failures_total, as an unreachable source
does; vigil_supervisor_config_reload_failed stays 0. The log tells them
apart: "line 93: unknown section [fleet_nonsense] (E_SECTION_UNKNOWN)".

7. Windows and Git: certificates (documentation)
------------------------------------------------
Git for Windows checks certificates with its own bundle, not the Windows
store: with a private CA, http.<url>.sslCAInfo is needed. MinGit uses
schannel, which demands a revocation check a private CA may not support,
and ignores sslCAInfo: http.sslBackend = openssl. Until then the instance
waits: "waiting for the first fetch ... SSL certificate OpenSSL verify
result: unable to get local issuer certificate (20)".
